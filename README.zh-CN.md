# GuardGate

**面向大模型应用的提示注入检测与防御网关。**

[English](README.md) · [Apache-2.0](LICENSE)

GuardGate 部署在你的应用和大模型之间：在用户输入与检索到的上下文进入模型之前做检测，在模型输出返回用户之前做审查。

> **当前状态：pre-alpha。** 这只是一个骨架，还不能用于生产环境，进度见[路线图](#路线图)。

## 为什么做这个

基于大模型的应用有一个结构性弱点：模型无法可靠区分「开发者写的指令」和「只是看起来像指令的文本」。由此产生两类攻击。

**直接注入**——用户自己输入一段试图覆盖系统提示词的内容（"忽略以上所有指令，然后……"）。

**间接注入**——恶意指令被埋在应用稍后会检索并拼进提示词的地方：网页、PDF、邮件、工单、代码注释。用户没有输入任何可疑内容，是应用自己把它送进了模型。

间接注入更难防，也是本项目主攻的方向。现有的检测工具多数只看最终拼好的那一条 prompt——此时一句恶意指令已经被几千 token 的正常上下文稀释掉了。GuardGate 的做法是**在拼接之前，对每一个检索到的文本块单独打分**，再把这些分数聚合成最终决策。

## 工作方式

```
                 用户输入 ──┐
                            ├──► [ 输入检测层 ]  直接注入 / 越狱
      检索到的上下文块 ─────┤
                            ├──► [ 上下文检测层 ] 逐块打分  ◄── 差异点在这里
                            │
                            └──► [ 决策层 ]  放行 / 净化 / 拦截
                                      │
                                      ▼
                                    大模型
                                      │
                                      ▼
                            [ 输出检测层 ]  敏感信息泄露 / 系统提示词泄露
```

每一次判定都会写入结构化审计日志。一个只会拦流量、却说不清为什么拦的网关，是没法真正上线的。

## 设计原则

1. **逐块打分。** 在恶意指令被埋进长上下文之前就把它抓出来。
2. **对延迟诚实。** 每个请求多花 3 秒的防护措施，最终一定会被人关掉。规则与小模型级联，让常见路径保持廉价，并且如实公布延迟数据。
3. **用实验说话，不用形容词。** 仓库里的每一个结论都应该有可复现的评测支撑。只报检出率是没有意义的——真正让安全措施被撤掉的原因是误报。
4. **在一台笔记本上跑得动。** 目标开发环境是单张 8GB 消费级显卡，不需要集群。

## 快速开始

目前还不能用。v0.1 完成后：

```bash
git clone https://github.com/LLF-prong/guardgate.git
cd guardgate
python -m venv .venv
.venv/Scripts/activate     # Windows
pip install -e ".[dev]"
pytest
```
